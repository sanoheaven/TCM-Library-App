# OCR 转 Markdown 结构保真规则

## 总则

原页图像是文字和版式关系的唯一判断依据。OCR、风险规则、双引擎差异、扫描全能王 Word 转录和模型输出只能辅助定位，不能替代人工核图。

## 扫描全能王 Word 辅助层

- 扫描全能王导出的 Word 可复用为**辅助转录层**：用于提供段落切分、可读文本候选、方名/药名间空格和潜在 OCR 差异。
- Word 重排后的页码、换行、页眉页脚和段落样式不是原 PDF 的页级证据；即使视觉渲染正常，也不得把它的页序或版式映射为 PDF 页码锚点。
- 冻结 OCR 源行仍是结构映射和硬校验的唯一输入。Word 候选不得覆盖 `text`、不得绕过逐字符守恒，也不得独自决定正文、评讲、图示或附方角色。
- Word 与 OCR 不一致时，只能登记为可追溯的 `word_candidate_text` / 差异项，并附原 PDF 页图定位；未经逐页核图确认，不得静默写入最终稿。
- 对附方，Word 中的药物空格可用于发现“连写”风险；药名、方名、序号和生僻字仍以原页逐字确认。无法建立可靠 PDF 页级对应时，Word 仅可作章节级候选。
- Word 必须以可复现方式渲染后使用；Windows 环境优先使用 LibreOffice `soffice.com` 的隔离用户配置进行无界面转换。渲染成功不等于原文核定。

## 评讲与正文

- 标签外默认是正文；评讲使用成对的 `BEGIN:评讲` / `END:评讲` 明文标签。
- `BEGIN` 必须紧贴以 `【评讲】` 或明确变体（如 `【总评讲】`）开头的源行之前；该原文标记必须保留。
- 评讲边界前后的短行独立判定，不按距离吸附；无法确认时标记 `needs_human_review`。
- 跨页评讲沿用稳定 `block_id`，每页闭合并在下一页重新开启，标注续接来源。
- 每个新出现的明确评讲标记必须开启新的 `block_id`；程序须拒绝或规范化模型将多个独立标记块复用为同一 ID 的输出，并留下警告。

## 结构与内容守恒

- 每条冻结 OCR 源行必须且只能分配一个角色：正文、评讲、标题、图示、附方或排除项。
- 标题、页眉页脚、图示和附方必须保存可审计的结构化等价记录。
- 标题不能吞掉相邻正文；页眉页脚仅保留 `EXCLUDED` 审计注释。
- 图示须保留节点、连线和方向关系；无法可靠还原时明确标为待人工确认。
- 方剂注号保持成对全角括号，附方药物分隔保留原书信息；方名、药名和生僻字逐字核图。
- `附方`标题后的连续编号条目必须锚定为 `formula`，不得因模型误判而落入评讲；跨页附方续接也须校验。

## 模型参与方式

## 通用预处理器（最小可用版）

`scripts/preprocess_structure_candidates.py` 只输出非绑定候选：评讲起点、附方标题与编号、页码候选、图示或标题风险。它不得直接分配最终角色、改写 OCR 源行或生成 Markdown；章节映射和页图核对仍是必经步骤。

### 稳定版关键 review 与上下文

稳定版的 `pre_child_content_requires_inheritance_review`、`missing_manifest_title`、`split_title_candidate` 与 `title_alias_candidate` 属于关键 review。每项必须由 resolution JSON 精确闭环：`rule_id`、`pdf_page`、`source_lines`、`resolution`、`evidence` 均为必填；缺任一字段或未精确匹配即作为 error 阻断。文字说明不能替代 resolution。

对子项起页运行时，预处理器自动将前一 PDF 页并入上下文；前页 OCR 或映射不可用即为 error。可重复传入 `--mapping-dir` 以按页读取父项和子项的独立映射目录。`title_aliases` 仅允许在 manifest 指定章节的起页匹配，且每个别名必须附页图证据；禁止全局模糊替换。

### 稳定版父子项边界门禁

- 使用本地章节 manifest 显式记录父项、子项及 PDF 起止页；不得按整页猜测父子项切换。仓库只保存通用模板，章节专用 manifest 与 resolution 不进入公开仓库。
- 子项标题前存在内容时必须输出继承复核提示，防止上一子项的跨页续文被归入新子项。
- 拆行标题、重复父题页眉、评讲中途变更角色均须程序报警。
- 带 `error` 的稳定版预处理结果不得登记为“完成待人工审核”，即使逐行硬校验为 0 错误。

模型只能输出逐行 JSON 角色映射，不得从整章 OCR 自由生成最终 Markdown。每项映射包含页码、行号、逐字符不变的原文、唯一角色、角色证据；评讲另含 `block_id`。

程序必须从冻结源行与映射重新计算行数、顺序、页码、行号、原文一致性、唯一角色、跨页续接、标签配对、遗漏、重复和未知角色。模型自行声明的“100% 覆盖”或“全部通过”不是审计证据。

仅在硬校验通过后由程序渲染 Markdown。自由生成稿和模型对照稿不得覆盖人工核验主稿或直接进入 Ingest。

## 发布门禁

进入后续提取前，至少满足：

1. 评讲标签成对，跨页续接完整；
2. 全部源行覆盖率 100%，遗漏、重复与未知角色为 0；
3. 页眉页脚未进入正文，标题与附方锚点匹配；
4. 图示已还原或明确待核，方剂注号与附方编号闭环；
5. 模型映射已通过程序硬校验；
6. 已完成逐页核图、独立复核和本轮共性问题闭环。

## 强制共性问题闭环

### 图示人工派生文字

- 图示可在逐页核图后合并为人工派生文字，展示行数可以不同于 OCR 行数。
- 派生文字必须记录 `diagram_group` 与全部 `DIAGRAM_SOURCE` 来源行；每条冻结 OCR 行仍须且只能有一个角色。
- 未核图时不得填写派生文字或推断关系，只能保留“待人工确认”。

每次运行后检查漏行、重复、原文改写、虚假审计结论、评讲边界、跨页续接、标题吞行、页眉页脚、图示、附方跨行及方药字符风险。确认的新共性问题必须同时形成规则说明、可执行检测和最小回归样例，然后重跑当前章和完整历史回归集。
